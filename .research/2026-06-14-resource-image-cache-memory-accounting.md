# Research: Resource Image Cache Memory Accounting

## Summary

The active resolved-image cache is `ImageResolveCache`, owned through `SurfaceResourceSession`. Its declared default capacity is `1024` entries (`lib/src/resources/resource_cache.dart:5`), its internal storage is a `Map<_ImageResolveCacheKey, ui.Image>` (`lib/src/resources/resource_cache.dart:18`), and its eviction loop removes entries while `_entries.length > _capacity` (`lib/src/resources/resource_cache.dart:56`). The cache key contains `resolverGeneration`, `resourceId`, and `resourceRevision` (`lib/src/resources/resource_cache.dart:7`), and current contract tables document the same owner/key/capacity shape as "1024 entries per active session" (`docs/contracts/resources.md:134`, `docs/contracts/resources.md:136`; `docs/contracts/cache_policy.md:37`, `docs/contracts/cache_policy.md:45`).

Resource descriptors already carry optional `byteLength` through public resource objects, frame descriptor facts, and resolver requests (`lib/src/contracts/public/canvas_resource.dart:17`, `lib/src/contracts/internal/frame_facts_port.dart:140`, `lib/src/frame/paint_asset_binding_service.dart:71`, `lib/src/resources/resource_resolver_adapter.dart:15`). The cache implementation does not accept `byteLength`, `ui.Image.width`, `ui.Image.height`, or a byte-size value in its `read` or `write` APIs (`lib/src/resources/resource_cache.dart:22`, `lib/src/resources/resource_cache.dart:42`). The scoped searches listed below found no `maximumSizeBytes`, byte-capacity counter, or total-byte eviction logic in `lib/src/resources/**`.

The engine-side lifecycle contract says returned `ui.Image` objects are app-owned and the engine never disposes app-provided images (`docs/contracts/public_api_v1.md:1984`, `docs/contracts/public_api_v1.md:1985`, `docs/contracts/public_api_v1.md:1986`). The production cache invalidation paths clear map entries (`lib/src/resources/resource_cache.dart:61`, `lib/src/resources/resource_cache.dart:65`) and `SurfaceResourceSession` calls those cache operations on resolver replacement, target/all invalidation, document replacement reset, drop, and dispose (`lib/src/resources/surface_resource_session.dart:168`, `lib/src/resources/surface_resource_session.dart:180`, `lib/src/resources/surface_resource_session.dart:185`, `lib/src/resources/surface_resource_session.dart:190`, `lib/src/resources/surface_resource_session.dart:201`, `lib/src/resources/surface_resource_session.dart:211`). A fixture explicitly checks that eviction, invalidation, resolver replacement, drop, and dispose leave the app-owned image undisposed (`test/resources/fixtures/app_owned_image_not_disposed_fixture.dart:24`, `test/resources/fixtures/app_owned_image_not_disposed_fixture.dart:30`, `test/resources/fixtures/app_owned_image_not_disposed_fixture.dart:32`, `test/resources/fixtures/app_owned_image_not_disposed_fixture.dart:35`, `test/resources/fixtures/app_owned_image_not_disposed_fixture.dart:39`, `test/resources/fixtures/app_owned_image_not_disposed_fixture.dart:42`, `test/resources/fixtures/app_owned_image_not_disposed_fixture.dart:45`).
