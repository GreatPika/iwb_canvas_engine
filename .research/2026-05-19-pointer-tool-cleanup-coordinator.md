# Research: Pointer Tool Cleanup Coordinator

## Summary

The new architecture documentation describes cleanup as a shared pointer-session concern plus tool-specific cleanup states. The documented cleanup-only inputs include cancel, load success, mode change, active-pointer `interactive=false`, dispose, stale terminal, invalid terminal, no-op, and non-committing paths; these clear preview/session state and release the active token before publishing public state, action, or repaint effects (`docs/diagrams/state_pointer_session.mmd:99`, `docs/diagrams/state_pointer_session.mmd:108`, `docs/diagrams/state_pointer_session.mmd:111`). No documented `PointerToolCleanupCoordinator` symbol was found in the inspected documentation; the documented names are pointer-session lifecycle, cleanup-only states, and tool-specific cleanup states (`docs/contracts/interaction_engine.md:83`, `docs/diagrams/state_pointer_session.mmd:99`).

The legacy implementation distributes cleanup across draw coordination, draw terminal routing, line pending state, move session terminal handling, runtime interruption, pointer-session detach, and event dispatch. Draw cleanup clears active previews through `resetGestureState`, with pending line ownership handled separately by token-aware line state (`legacy/iwb_canvas_engine/lib/src/interactive/internal/interactive_draw_coordinator.dart:109`, `legacy/iwb_canvas_engine/lib/src/interactive/internal/interactive_draw_coordinator.dart:116`, `legacy/iwb_canvas_engine/lib/src/interactive/internal/interactive_draw_line_engine.dart:101`). Move and marquee cleanup compute scene-vs-overlay repaint effects before clearing gesture state (`legacy/iwb_canvas_engine/lib/src/interactive/internal/interactive_move_session.dart:223`), while runtime interruption and session detach schedule public/scene/overlay notifications according to the cleared state (`legacy/iwb_canvas_engine/lib/src/interactive/internal/interactive_runtime.dart:209`, `legacy/iwb_canvas_engine/lib/src/interactive/internal/interactive_runtime.dart:229`, `legacy/iwb_canvas_engine/lib/src/interactive/internal/interactive_runtime.dart:259`).

Existing verification covers several cleanup behaviors through interactive tests plus two AST audits. The tests assert cleanup after thrown draw commits, action emission failure, line pending owner isolation, move cancel behavior, marquee baseline restore, dispose fail-fast, and zero-preview terminal no-repaint cases (`legacy/iwb_canvas_engine/test/interactive/core/interactive_draw_terminal_cleanup_test.dart:155`, `legacy/iwb_canvas_engine/test/interactive/core/scene_controller_interactive_line_pending_cancel_test.dart:375`, `legacy/iwb_canvas_engine/test/interactive/core/scene_controller_interactive_move_preview_invariants_test.dart:100`, `legacy/iwb_canvas_engine/test/interactive/core/scene_controller_interactive_move_preview_invariants_test.dart:167`). The AST audits classify commit/emit/notify/dispatch calls and cleanup calls by function-name shape, then report cleanup-order risks unless cleanup is protected by `finally` or ordered before hazardous effects (`legacy/iwb_canvas_engine/tool/audit_terminal_cleanup_safety.dart:275`, `legacy/iwb_canvas_engine/tool/audit_terminal_cleanup_safety.dart:282`, `legacy/iwb_canvas_engine/tool/audit_post_commit_cleanup_order.dart:332`, `legacy/iwb_canvas_engine/tool/audit_post_commit_cleanup_order.dart:336`, `legacy/iwb_canvas_engine/tool/audit_post_commit_cleanup_order.dart:345`).

## Detailed Findings

### 1. Documented Pointer Session Cleanup Contract

- **Location**: primary `docs/contracts/interaction_engine.md:83`; related `docs/diagrams/state_pointer_session.mmd:99`.
- **Description**: The contract describes a pointer session lifecycle where active pointers move to terminal commit, cancelled, invalid terminal cleanup, or disposed states (`docs/contracts/interaction_engine.md:88`, `docs/contracts/interaction_engine.md:91`, `docs/contracts/interaction_engine.md:93`, `docs/contracts/interaction_engine.md:96`). Terminal admission requires the active pointer token and current `controllerEpoch`; stale token or epoch mismatch may clean up only and cannot create a commit intent (`docs/contracts/interaction_engine.md:107`). Cleanup that is already a no-op publishes no new public state snapshot (`docs/contracts/interaction_engine.md:122`).
- **Dependencies**: The documented pointer session depends on normalized `CanvasPointerSample`, `controllerEpoch`, public preview variants, and `EditKernel` for commits (`docs/contracts/interaction_engine.md:106`, `docs/contracts/interaction_engine.md:107`, `docs/contracts/interaction_engine.md:118`, `docs/contracts/interaction_engine.md:120`).
- **Data flow**: Pointer sample -> active pointer routing -> terminal admission -> cleanup-only, commit, or dispose path -> preview/session clear -> active token release -> public state/action/repaint effects (`docs/diagrams/state_pointer_session.mmd:99`, `docs/diagrams/state_pointer_session.mmd:108`, `docs/diagrams/state_pointer_session.mmd:111`, `docs/diagrams/state_pointer_session.mmd:118`, `docs/diagrams/state_pointer_session.mmd:129`).

### 2. Documented Repaint Targets And Load Cleanup

- **Location**: primary `docs/contracts/interaction_engine.md:142`; related `docs/diagrams/seq_load_document_success.mmd:40`.
- **Description**: Public preview variants are produced by `InteractionEngine`; marquee, pencil, marker, pending line, line preview, and eraser corridor are overlay-only, while selected move is main-scene only (`docs/contracts/interaction_engine.md:144`, `docs/contracts/interaction_engine.md:150`, `docs/contracts/interaction_engine.md:158`). `loadDocument` success performs interaction interrupt only after preparation succeeds, clears preview, bumps `previewRevision` if active, and publishes post-install state including preview cleanup revision if changed (`docs/diagrams/seq_load_document_success.mmd:40`, `docs/diagrams/seq_load_document_success.mmd:42`, `docs/diagrams/seq_load_document_success.mmd:44`, `docs/diagrams/seq_load_document_success.mmd:69`).
