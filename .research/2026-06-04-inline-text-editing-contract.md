# Research: Inline Text Editing Contract

## Summary

Text rendering layout currently has two separate sources of geometry. The actual rendered text layout is computed by Flutter `TextPainter` in the frame render-family cache (`lib/src/frame/render_family_caches.dart:104`, `lib/src/frame/render_family_caches.dart:120`) and painted from the cached painter (`lib/src/frame/main_frame_record_painter.dart:140`, `lib/src/frame/main_frame_record_painter.dart:155`). Text bounds used by spatial, hit testing, selection chrome, and context-action targets are computed by `GeometryPolicy._textBounds` from a formula based on text length, font size, max width, and line height (`lib/src/geometry/geometry_policy.dart:328`, `lib/src/geometry/geometry_policy.dart:336`), not from the `TextPainter` layout.

The current public context-action flow treats double tap as a context request trigger, not as an edit command. The runtime emits `CanvasContextActionRequested` with a target snapshot and bounds (`lib/src/contracts/public/canvas_actions.dart:175`, `lib/src/contracts/public/canvas_actions.dart:211`), and the application decides what to do with the target; existing docs state that the application may show a context menu or a Flutter text editor when the target is `CanvasTextElement` (`docs/contracts/public_api_v1.md:2367`, `docs/contracts/public_api_v1.md:2369`). The current example immediately opens an app-owned text edit session for text targets (`example/lib/src/canvas_example_view_model.dart:625`, `example/lib/src/canvas_example_view_model.dart:631`).

The example overlay is not engine-level. It positions a Flutter `TextField` from `target.boundsWorld` and camera offset (`example/lib/src/canvas_text_edit_overlay.dart:62`, `example/lib/src/canvas_text_edit_overlay.dart:63`), sets width from `bounds.width` (`example/lib/src/canvas_text_edit_overlay.dart:85`), and remeasures editor height with another `TextPainter` (`example/lib/src/canvas_text_edit_overlay.dart:154`, `example/lib/src/canvas_text_edit_overlay.dart:180`). No public `CanvasTextEditSession`, `CanvasTextEditingPort`, or `CanvasTextEditingOverlay` symbol was found in `lib/`, `test/`, or `example/`; only example-owned `CanvasExampleTextEditSession` and `CanvasTextEditOverlay` exist (`example/lib/src/canvas_example_view_model.dart:689`, `example/lib/src/canvas_text_edit_overlay.dart:10`).

## Detailed Findings

### 1. Text Element Data And Frame Facts

- **Location**: primary `lib/src/contracts/public/canvas_element.dart:138`; additional `lib/src/contracts/internal/frame_facts_port.dart:45`, `lib/src/store/family_tables.dart:409`.
- **Description**: `CanvasTextElement` exposes the public text fields used by rendering and editing: `text`, `fontSize`, `color`, `align`, `textDirection`, `isBold`, `isItalic`, `isUnderline`, `fontFamily`, `maxWidth`, and `lineHeight` (`lib/src/contracts/public/canvas_element.dart:138`, `lib/src/contracts/public/canvas_element.dart:203`). `FrameElementFacts` carries matching text fields across the frame read boundary (`lib/src/contracts/internal/frame_facts_port.dart:71`, `lib/src/contracts/internal/frame_facts_port.dart:81`, `lib/src/contracts/internal/frame_facts_port.dart:113`, `lib/src/contracts/internal/frame_facts_port.dart:123`). Store `TextRow` preserves element text/style fields (`lib/src/store/family_tables.dart:409`, `lib/src/store/family_tables.dart:421`).
- **Dependencies**: Public text elements use validation helpers before admission (`lib/src/contracts/public/canvas_element.dart:163`, `lib/src/contracts/public/canvas_element.dart:193`). Runtime copies store facts into `FrameElementFacts`, including text/style fields (`lib/src/runtime/runtime_root.dart:493`, `lib/src/runtime/runtime_root.dart:535`, `lib/src/runtime/runtime_root.dart:545`).
- **Data flow**: `CanvasTextElement` -> `TextRow` -> store facts -> `RuntimeRoot.resolveElement` -> `FrameElementFacts`.
- **Evidence consequence**: The public element snapshot already contains text content and styling fields that an app can copy into a Flutter editor (`lib/src/contracts/public/canvas_element.dart:203`, `example/lib/src/canvas_text_edit_overlay.dart:94`, `example/lib/src/canvas_text_edit_overlay.dart:115`). It does not contain measured paint layout dimensions or baselines.

### 2. Render Text Layout And Paint Path

- **Location**: primary `lib/src/frame/render_family_caches.dart:104`; additional `lib/src/frame/main_frame_record_painter.dart:133`.
- **Description**: `TextRenderRow` stores render-time text fields and a `TextLayoutCacheKey` (`lib/src/frame/render_element_record.dart:48`, `lib/src/frame/render_element_record.dart:65`). `_textRow` converts `FrameElementFacts` into `TextRenderRow` with defaults (`lib/src/frame/render_element_record.dart:233`, `lib/src/frame/render_element_record.dart:251`). `_textPainterFor` constructs `TextPainter`, builds a `TextSpan`/`TextStyle`, applies alignment and direction, and calls `layout(maxWidth: row.maxWidth ?? double.infinity)` (`lib/src/frame/render_family_caches.dart:104`, `lib/src/frame/render_family_caches.dart:120`).
- **Dependencies**: `TextLayoutCache` stores `TextLayoutCacheEntry`, whose `painter` field is a `TextPainter` (`lib/src/frame/frame_cache.dart:172`, `lib/src/frame/frame_cache.dart:295`, `lib/src/frame/frame_cache.dart:299`). The cache key includes text, font size, opacity-adjusted color, alignment, direction, bold/italic/underline, font family, max width, and line height (`lib/src/frame/frame_cache.dart:193`, `lib/src/frame/frame_cache.dart:219`, `lib/src/frame/frame_cache.dart:230`, `lib/src/frame/frame_cache.dart:244`).
- **Data flow**: `FrameElementFacts` -> `TextRenderRow` -> `TextLayoutCacheKey` -> `TextLayoutCacheEntry(TextPainter)` -> `RenderPrimitiveCacheSnapshot` -> `_paintTextRecord`.
- **Evidence consequence**: The production paint path reads an already laid-out painter from `renderPrimitives.textLayouts[row.layoutCacheKey]` (`lib/src/frame/main_frame_record_painter.dart:139`, `lib/src/frame/main_frame_record_painter.dart:140`). It then creates local bounds from `painter.width` and `painter.height` and paints at `localBounds.topLeft` (`lib/src/frame/main_frame_record_painter.dart:150`, `lib/src/frame/main_frame_record_painter.dart:155`). No production `drawParagraph` or `drawText` call was found by search.

### 3. Text Bounds Sources

- **Location**: primary `lib/src/geometry/geometry_policy.dart:25`; additional `lib/src/geometry/geometry_policy.dart:328`.
- **Description**: `GeometryPolicy.boundsFor` gets local bounds by element kind, transforms them, and returns `GeometryBounds` with `localBounds`, `hitBoundsWorld`, and `paintBoundsWorld` (`lib/src/geometry/geometry_policy.dart:25`, `lib/src/geometry/geometry_policy.dart:38`, `lib/src/geometry/geometry_policy.dart:45`). For text, local bounds are formula-based: width is `facts.maxWidth ?? text.length * fontSize * 0.5`, height is `fontSize * (facts.lineHeight ?? 1)`, and the rect is centered at zero (`lib/src/geometry/geometry_policy.dart:328`, `lib/src/geometry/geometry_policy.dart:331`, `lib/src/geometry/geometry_policy.dart:334`, `lib/src/geometry/geometry_policy.dart:336`).
- **Dependencies**: `RenderElementRecord.fromFacts` calls `geometryPolicy.boundsFor(facts)` and stores `paintBoundsWorld` and `hitBoundsWorld` (`lib/src/frame/render_element_record.dart:151`, `lib/src/frame/render_element_record.dart:155`, `lib/src/frame/render_element_record.dart:165`, `lib/src/frame/render_element_record.dart:166`). Selection decoration builds records from facts and uses `record.paintBoundsWorld` (`lib/src/frame/selection_decoration_planner.dart:182`, `lib/src/frame/selection_decoration_planner.dart:195`, `lib/src/frame/selection_decoration_planner.dart:196`).
- **Data flow**: `FrameElementFacts` -> `GeometryPolicy._textBounds` -> `GeometryBounds` -> render records, spatial entries, selection decoration, context targets.
- **Evidence consequence**: The geometry bounds used by paint admission, selection frame, hit candidates, and context targets are not derived from the `TextPainter` dimensions that actually render text. The paint path uses `painter.width` and `painter.height` (`lib/src/frame/main_frame_record_painter.dart:150`, `lib/src/frame/main_frame_record_painter.dart:153`), while geometry uses the formula at `lib/src/geometry/geometry_policy.dart:328`.

### 4. Paint, Hit, Selection, And Context Bounds

- **Location**: primary `lib/src/geometry/spatial_entry.dart:25`; additional `lib/src/runtime/runtime_interaction_read_adapter.dart:399`.
- **Description**: A spatial entry creates separate memberships: paint membership from `paintBoundsWorld`, hit membership from `hitBoundsWorld`, and context membership from `hitBoundsWorld` (`lib/src/geometry/spatial_entry.dart:36`, `lib/src/geometry/spatial_entry.dart:41`, `lib/src/geometry/spatial_entry.dart:65`, `lib/src/geometry/spatial_entry.dart:86`). Hit testing gates on `hitBoundsWorld`, then exact box-family hits for text use local bounds from `GeometryPolicy` (`lib/src/geometry/hit_test_policy.dart:94`, `lib/src/geometry/hit_test_policy.dart:99`, `lib/src/geometry/hit_test_policy.dart:193`, `lib/src/geometry/hit_test_policy.dart:199`).
- **Dependencies**: Context target reads query the context spatial index, exact-hit with `HitTestPolicy`, then publish content target `boundsWorld` as `geometryPolicy.boundsFor(hitFacts).paintBoundsWorld` (`lib/src/runtime/runtime_interaction_read_adapter.dart:403`, `lib/src/runtime/runtime_interaction_read_adapter.dart:432`, `lib/src/runtime/runtime_interaction_read_adapter.dart:450`, `lib/src/runtime/runtime_interaction_read_adapter.dart:455`). `ContextActionRouter` copies those bounds into public `CanvasContentElementContextActionTarget.boundsWorld` (`lib/src/interaction/context_action_router.dart:160`, `lib/src/interaction/context_action_router.dart:167`).
- **Data flow**: geometry bounds -> spatial paint/hit/context indexes -> hit policy -> `ContextTargetReadFacts` -> public `CanvasContentElementContextActionTarget.boundsWorld`.
- **Evidence consequence**: Paint admission and public context/edit target bounds use `paintBoundsWorld`, while hit and context lookup use `hitBoundsWorld` (`lib/src/geometry/spatial_entry.dart:41`, `lib/src/geometry/spatial_entry.dart:67`, `lib/src/geometry/spatial_entry.dart:88`). Both values originate from formula-based text bounds, not from render text layout.
