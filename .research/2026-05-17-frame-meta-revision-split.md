# Research: Deferred Frame Meta Revision Split

## Summary

The current architecture documents `frameMetaRevision` as an internal v1 aggregate for frame-affecting persisted document metadata such as background and grid. It is not part of public `CanvasRuntimeRevisions`, whose public domains are limited to `document`, `selection`, `preview`, `viewCamera`, `resourceVisual`, `interaction`, and `epoch`.

Frame rendering currently captures `frameMetaRevision` in `CapturedMainFrame` and uses frame/cache-specific facts for static background work, while ordinary committed element paint plans are keyed by structural, bounds, element visual, viewport, and device inputs. The contracts repeatedly state that `frameMetaRevision`, runtime view camera revision, and runtime view camera offset must not be `PaintPlanCache` key components.

Runtime view camera and persisted document camera are documented as separate ownership domains. `CanvasCameraPort.setOffset/panBy` updates runtime view camera state and public `state.revisions.viewCamera`; `CanvasEdit.setCameraOffset` updates persisted document camera through the document edit path. `loadDocument` initializes runtime view camera from persisted document camera on success, and `readDocument` projects the persisted camera rather than the current runtime view camera.

### 4. Cache Policy And Invalidation

### 6. Runtime View Camera And Persisted Document Camera Ownership

- **Location**: primary `docs/architecture/01_runtime_ownership.md:71`; additional `docs/architecture/01_runtime_ownership.md:75`, `docs/architecture/01_runtime_ownership.md:81`
- **Description**: The architecture documents a deliberate split between runtime view camera and persisted document camera (`docs/architecture/01_runtime_ownership.md:71`). Runtime view camera is owned by `RuntimeRoot/CanvasCameraPort`, is published through `state.revisions.viewCamera`, repaints affected surfaces, and does not dirty document state or invalidate `CanvasDocument` projection (`docs/architecture/01_runtime_ownership.md:74`, `docs/architecture/01_runtime_ownership.md:75`, `docs/architecture/01_runtime_ownership.md:76`, `docs/architecture/01_runtime_ownership.md:77`, `docs/architecture/01_runtime_ownership.md:78`). Persisted document camera is owned by `DocumentStoreKernel` as committed document content, is stored in `CanvasDocument` and schema v1, changes only through `CanvasEdit.setCameraOffset` or document replacement, and is read back through `readDocument` (`docs/architecture/01_runtime_ownership.md:80`, `docs/architecture/01_runtime_ownership.md:81`, `docs/architecture/01_runtime_ownership.md:82`, `docs/architecture/01_runtime_ownership.md:83`, `docs/architecture/01_runtime_ownership.md:84`).
- **Dependencies**: `DocumentMetaRecord` stores `persistedCameraOffset` as a persisted document fact (`docs/architecture/03_data_model.md:66`, `docs/architecture/03_data_model.md:69`). Runtime view camera is not stored in `CommittedDocument`; it is runtime state owned by `RuntimeRoot` through the camera boundary (`docs/architecture/03_data_model.md:110`, `docs/architecture/03_data_model.md:111`).
- **Data flow**: `CanvasCameraPort.setOffset/panBy` touches runtime view camera, increments `state.revisions.viewCamera`, does not update spatial state, does not evict projection, and schedules main plus overlay repaint (`docs/contracts/operation_matrix.md:62`). `CanvasEdit.setCameraOffset` touches persisted document camera, increments `state.revisions.document`, advances internal projection, does not update spatial state, evicts projection, and causes no immediate view-camera repaint unless current view is explicitly reinitialized by load (`docs/contracts/operation_matrix.md:61`).
