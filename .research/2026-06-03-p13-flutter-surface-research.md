# Research: P13 Flutter Surface

## Summary

The repository already contains runtime, frame, resource, and interaction seams that P13 references: `CanvasRuntime` creates a `RuntimeRoot` and attaches it through an API-local bridge (`lib/src/api/canvas_runtime.dart:31`, `lib/src/api/canvas_runtime.dart:32`, `lib/src/api/canvas_runtime_frame_bridge.dart:3`), `RuntimeRoot` exposes resource-free main and overlay frame builders (`lib/src/runtime/runtime_root.dart:279`, `lib/src/runtime/runtime_root.dart:296`), `SurfaceResourceSession` owns resolver/cache/generation/drop behavior (`lib/src/resources/surface_resource_session.dart:17`, `lib/src/resources/surface_resource_session.dart:167`, `lib/src/resources/surface_resource_session.dart:188`), and interaction cleanup already contains the `interactiveDisabled` pending-line preservation branch (`lib/src/interaction/pointer_tool_cleanup_coordinator.dart:38`, `lib/src/interaction/pointer_tool_cleanup_coordinator.dart:71`).

The current public `CanvasSurface` implementation is still in `lib/src/api/canvas_surface.dart` and is a passive widget bridge. It imports frame painters directly (`lib/src/api/canvas_surface.dart:4`, `lib/src/api/canvas_surface.dart:5`), observes `runtime.state`, looks up `RuntimeRoot` through the frame bridge, builds resource-free frame outputs, and passes them to `CustomPaint` (`lib/src/api/canvas_surface.dart:49`, `lib/src/api/canvas_surface.dart:52`, `lib/src/api/canvas_surface.dart:62`, `lib/src/api/canvas_surface.dart:68`, `lib/src/api/canvas_surface.dart:75`). It does not contain a Flutter pointer adapter, single-active-surface attach gate, `SurfaceResourceSession` lifecycle wiring, or resolver-backed frame path in the inspected code (`lib/src/api/canvas_surface.dart:38`, `lib/src/api/canvas_surface.dart:97`).

The repository also contains several documented/guarded surface facts that are not aligned in one place. Architecture layout names `lib/src/surface/**` as the target surface owner (`docs/architecture/02_package_boundaries.md:153`, `docs/architecture/02_package_boundaries.md:158`), while no `lib/src/surface` directory exists in the current `find lib/src -maxdepth 2 -type d` command output. P13 docs list `surface.pointer_samples_normalized_before_runtime` and `surface.interactive_false_pending_line_preserved` (`docs/implementation/p13_flutter_surface.md:125`, `docs/implementation/p13_flutter_surface.md:126`), but those ids are not registered in `guardrail_registry.dart` or routed in `guardrail_executor.dart` based on searches over those files. `dart run tool/architecture_graph/check.dart --phase P13` currently fails with missing `flutter.surface` and `flutter.surface.drives_runtime_ports` obligations.
