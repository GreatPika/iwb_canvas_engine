# Research: Legacy AST Guardrail Patterns

## Summary
The legacy guardrail system is a fixed sequence of metadata-bearing `GuardrailRule` values. The runner creates one `GuardrailContext`, one `GuardrailRunState`, runs every rule from `guardrailRuleInventory`, and stops at the first returned `GuardrailViolation` (`legacy/iwb_canvas_engine/tool/src/guardrails/guardrails_runner.dart:11`, `legacy/iwb_canvas_engine/tool/src/guardrails/guardrails_runner.dart:16`, `legacy/iwb_canvas_engine/tool/src/guardrails/guardrails_runner.dart:22`, `legacy/iwb_canvas_engine/tool/src/guardrails/guardrail_rule_inventory.dart:9`).

The observed AST guardrail patterns split into three levels. Parsed AST checks use `ParsedUnitResult`, directive nodes, visitors, and offsets for structural rules and import boundaries (`legacy/iwb_canvas_engine/tool/src/guardrails/support/guardrail_ast_utils.dart:13`, `legacy/iwb_canvas_engine/tool/src/guardrails/core/guardrail_runner_support.dart:231`). Resolver-backed checks use `ResolvedUnitResult`, `ResolvedLibraryResult`, analyzer `Element`, `DartType`, and `staticType` for ownership, public surface, signature leak, and semantic sequence checks (`legacy/iwb_canvas_engine/tool/src/guardrails/support/guardrail_context.dart:60`, `legacy/iwb_canvas_engine/tool/src/guardrails/support/guardrail_context.dart:76`, `legacy/iwb_canvas_engine/tool/src/guardrails/core/resolved_type_leak_traversal.dart:6`, `legacy/iwb_canvas_engine/tool/src/guardrails/core/semantic_sequence_routing_support.dart:370`). Violation reporting normalizes AST offsets or analyzer elements back to repository-relative paths and line numbers (`legacy/iwb_canvas_engine/tool/src/guardrails/support/guardrail_ast_utils.dart:72`, `legacy/iwb_canvas_engine/tool/src/guardrails/core/guardrail_element_utils.dart:37`, `legacy/iwb_canvas_engine/tool/src/guardrails/core/guardrail_element_utils.dart:45`).

The interactive family is the densest resolver-backed example. It groups many boundary checks under one `part` library, imports analyzer AST/visitor/element/type APIs once, and combines parsed declarations, resolved element ownership, `RecursiveAstVisitor` collectors, file specs, semantic sequence analysis, and exact surface validation (`legacy/iwb_canvas_engine/tool/src/guardrails/rules/interactive/mutation_boundary_rules.dart:3`, `legacy/iwb_canvas_engine/tool/src/guardrails/rules/interactive/mutation_boundary_rules.dart:24`, `legacy/iwb_canvas_engine/tool/src/guardrails/rules/interactive/mutation_boundary_rules.dart:49`).
