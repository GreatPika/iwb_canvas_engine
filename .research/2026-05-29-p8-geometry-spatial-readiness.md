# Research: P8 Geometry And Spatial Readiness

## Summary

P8 is documented as the phase that introduces geometry, hit-test, paint admission, eraser geometry foundations, and the spatial candidate lookup owner before frame rendering and interaction consume bounded element queries (`docs/implementation/p8_geometry_and_spatial.md:5`). Its direct dependencies are already stated as P2 public DTOs, P4 committed facts and revisions, P5 touched sets and typed invalidation effects, and P7 resource/image rows (`docs/implementation/p8_geometry_and_spatial.md:25`).

The current runtime infrastructure already provides several P8 inputs: compact committed element/resource rows, revision domains, immutable read ports, stale handle rejection, edit-produced `TouchedSet` data, typed spatial delivery effects, and resource image/session seams (`lib/src/store/document_store_kernel.dart:20`, `lib/src/contracts/internal/frame_facts_port.dart:144`, `lib/src/contracts/internal/touched_set.dart:3`, `lib/src/contracts/internal/commit_delivery.dart:23`, `lib/src/resources/surface_resource_session.dart:17`). The P8 geometry/spatial owners themselves remain future scope in architecture metadata, and the source tree does not currently contain `lib/src/geometry/**`, `test/geometry/**`, or `test/spatial/**` (`docs/architecture/architecture_graph.yaml:380`, `docs/architecture/architecture_graph.yaml:386`).

Documentation and diagrams are ahead of implementation: P8 contracts, diagrams, donors, expected tests, and guardrail IDs are registered, while current root-package proof files and guardrail-runner routes for P8 are not present (`docs/verification/tests.md:162`, `docs/verification/tests.md:283`, `docs/verification/guardrails.md:65`, `tool/guardrails/src/guardrail_registry.dart:35`). A follow-up diagram and diagnostics-contract pass resolved the intended P8 diagnostics posture, the P12 ownership of eraser terminal no-partial proof, and the `SpatialKernel` owner/path metadata cleanup: graph metadata now names `SpatialKernel`, and the C4 component view uses `lib/src/geometry/` for that owner (`docs/contracts/diagnostics.md:88`, `docs/contracts/diagnostics.md:92`, `docs/implementation/p12_eraser_and_text_request.md:99`, `docs/architecture/architecture_graph.yaml:393`, `docs/diagrams/c4_component_runtime.mmd:24`).

## Detailed Findings

### 1. P8 Contract Surface

- **Location**: primary `docs/implementation/p8_geometry_and_spatial.md:1`; supporting contracts `docs/contracts/geometry.md:43`, `docs/contracts/spatial_kernel.md:39`.
- **Description**: P8 scope includes `GeometryPolicy`, `HitTestPolicy`, transform/local/hit/paint bounds policy, exact family hit tests, paint admission, eraser primitives, `SpatialKernel`, `TileIndex`, `OutlierIndex`, `SpatialMembership`, touched spatial update, stale candidate rejection, fallback query budget, and excludes global scene traversal or legacy scene-order logic (`docs/implementation/p8_geometry_and_spatial.md:10`, `docs/implementation/p8_geometry_and_spatial.md:23`).
- **Dependencies**: P8 depends on P4 committed facts/revisions, P5 touched sets and typed invalidation effects, and P7 resource/image rows (`docs/implementation/p8_geometry_and_spatial.md:27`, `docs/implementation/p8_geometry_and_spatial.md:30`).
- **Data flow**: P8 contracts read runtime data model, geometry policy, spatial kernel, and verification tests as source inputs (`docs/implementation/p8_geometry_and_spatial.md:32`, `docs/implementation/p8_geometry_and_spatial.md:37`).
- **Geometry obligations**: Geometry policy defines constants for hit slop, max path hit samples, spatial cell size, max cells per element, and max query cells (`docs/contracts/geometry.md:45`). It specifies point/context-action eligibility, content-only hit ordering, exact box/image/text/rect behavior, line/stroke/path hit behavior, paint admission, marquee selection, eraser geometry, and eraser exact-check budgets (`docs/contracts/geometry.md:55`, `docs/contracts/geometry.md:67`, `docs/contracts/geometry.md:91`, `docs/contracts/geometry.md:105`, `docs/contracts/geometry.md:136`, `docs/contracts/geometry.md:147`, `docs/contracts/geometry.md:157`, `docs/contracts/geometry.md:167`).
- **Spatial obligations**: Spatial kernel is documented as `SpatialKernel` with hit/paint tile indexes, hit/paint outliers, `entriesById`, and `structuralRevision` (`docs/contracts/spatial_kernel.md:41`). Tile policy defines `cellSize = 256`, outlier behavior above 1024 covered tiles, query fallback above 50000 tiles, `maxFallbackCandidates = 4096`, touched-id-only ordinary edits, and replacement/load rebuild paths (`docs/contracts/spatial_kernel.md:53`). The staged update algorithm compiles a delta from `TouchedSet`, validates ids/generations/revisions, applies removals/additions atomically, marks invalid indexes on failure, and returns typed budget-exceeded results instead of partial candidates (`docs/contracts/spatial_kernel.md:67`).

## Observed Architecture Facts

- Pattern observed: runtime composition meets store, edit, selection, and resource owners in `RuntimeRoot`, while read access is exposed through narrow internal ports (`lib/src/runtime/runtime_root.dart:43`, `lib/src/runtime/runtime_root.dart:150`, `lib/src/runtime/runtime_root.dart:151`).
- Pattern observed: committed element rows are materialized into immutable read facts instead of exposing store-owned row objects directly (`lib/src/runtime/runtime_root.dart:233`, `lib/src/runtime/runtime_root.dart:246`).
- Pattern observed: edit commits emit typed downstream effects, including spatial effects, without owning concrete spatial implementation (`lib/src/edit/commit_compiler.dart:56`, `lib/src/edit/commit_plan.dart:34`).
- Data flow: edit mutation -> `TouchedSet` -> `CommitPlan` -> store install -> `CommitDeliveryResult` -> typed post-commit effects (`lib/src/edit/touched_set_builder.dart:97`, `lib/src/edit/commit_compiler.dart:9`, `lib/src/edit/commit_applier.dart:25`, `lib/src/contracts/internal/commit_delivery.dart:3`).
- Data flow: spatial/hit candidate future path is documented as query -> revision/generation gate -> tile/outlier union -> candidate budget gate -> typed result (`docs/contracts/spatial_kernel.md:95`, `docs/diagrams/dfd_spatial_query_budget.mmd:20`).
- Key dependencies: P8 geometry/spatial is bounded by public/API dependency guardrails, contract-owner forbidden dependencies, and next-owned rows/order tokens rather than legacy scene traversal (`docs/architecture/architecture_graph.yaml:1050`, `docs/architecture/architecture_graph.yaml:1259`, `docs/contracts/geometry.md:38`, `docs/implementation/p8_geometry_and_spatial.md:105`).
