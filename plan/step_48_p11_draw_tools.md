# Change Contract

## Goal

Implement P11 draw tools so public consumers using the root package import can enter draw mode, draw pencil strokes, draw marker strokes, create two-tap lines, observe public draw previews while drawing, receive committed stroke/line document elements, and receive typed draw action events only after accepted document state has been installed.

## Classification

Profile: BEHAVIOR_CHANGE

Obligations:

- SEAM_MIGRATION: retire the P10 draw-pointer no-op by moving pencil, marker, and line behavior into the existing interaction, cleanup, runtime, edit, action, and frame seams instead of adding a draw-local controller or direct store mutation path.
- PUBLIC_API_CHANGE: existing public draw declarations become operational through `CanvasRuntime.tools`, `runtime.preview`, `runtime.state`, `runtime.readDocument()`, and `runtime.actions` without adding public API names.

## Boundaries

Owner:

`InteractionEngine` under `lib/src/interaction/**` owns draw-mode pointer admission, active pointer sessions, pending line state, draw preview state, preview revision, interaction setting revision, cleanup request orchestration, and the only call path into `PointerToolCleanupCoordinator`. `DrawStrokeMachine` owns pencil/marker stroke lifecycle calculations and point capping only. `LineMachine` owns two-tap line lifecycle calculations and immutable pending-line facts only. `RuntimeRoot` owns public state publication orchestration, generated element id allocation call site, interaction commit delivery, action stream delivery, runtime timestamp output clock, and the runtime-side surface cleanup entry point. `CanvasSurface` owns only the Flutter widget observation of `interactive true -> false` and delegates cleanup to runtime; it does not own cleanup policy, raw gesture recognition, pointer routing implementation, or document mutation. `EditKernel` owns atomic document mutation and rollback. `DocumentStoreKernel` owns committed document state and generated id cursor. `RuntimeActionFinalizer` owns draw action id/timestamp finalization and payload mapping.

In Scope:

Add `draw_stroke_machine.dart` and `line_machine.dart`; repair `PointerSession` payload cohesion before adding draw payloads; add explicit pending line state under `InteractionEngine`; extend interaction pointer context/admission with draw stroke and line commit intents plus a narrow timestamp resolver for accepted pending line previews; implement pencil and marker stroke preview/commit/cancel behavior; implement line first-tap pending preview, endpoint preview, commit, cancel, stale/no-op/invalid cleanup behavior; add internal draw action intents and runtime finalizer mapping; deliver draw commits through `EditKernel.prepareInteractionCommit` and `CanvasEdit.addElement`; add the narrow `CanvasSurface(interactive true -> false)` cleanup bridge required to prove P11 pending-line preservation and line-owned cleanup; preserve centralized cleanup through the P10 coordinator, including exact `PointerCleanupReason.cancel`; update focused tests, guardrails, public incremental smoke, graph/docs/diagrams, generated docs, and verification inventory needed for P11 closure.

Out of Scope:

Do not implement eraser deletion, text/context-action request behavior, Flutter raw gesture recognition beyond the narrow `interactive true -> false` cleanup bridge, new public draw command APIs, new public DTO names, new document/schema element families, direct store/family-table mutation, draw-local cleanup policy, scene-controller facades, whole legacy interactive runtime structure, scene builder public architecture, whole scene codec structure, or whole scene store controller structure. Do not change programmatic `CanvasEdit.addElement` action silence. Do not require generated element ids to be gapless after failures.

Compatibility:

The public package remains source-compatible. P11 changes behavior through already exported declarations: `CanvasInteractionMode.draw`, `CanvasDrawTool.pencil`, `CanvasDrawTool.marker`, `CanvasDrawTool.line`, `CanvasDrawStyle`, `CanvasToolPort.handlePointer`, draw preview variants, `CanvasStrokeElement`, `CanvasLineElement`, `CanvasActionType.drawPencil`, `CanvasActionType.drawMarker`, `CanvasActionType.drawLine`, and draw action payloads. Existing P10 draw-pointer no-op compatibility is retired only for pencil, marker, and line. Eraser, context-action request, and guarded text-edit commit behavior remain later-phase scope. Preview changes must not advance document revision before commit. Accepted draw commits publish public state before action events.

Order Constraints:

Repair session payload cohesion, cleanup cancel vocabulary, pending-line ownership fields, and the pointer context timestamp seam before adding stroke/line routing. Add internal draw action intents and finalizer mapping before runtime draw commit delivery depends on them. Implement and prove stroke lifecycle before marker-specific assertions because marker reuses the stroke lifecycle with different style values; add stroke commit admission only after `DrawStrokeMachine` owns concrete stroke result types. Implement line first-tap pending state before endpoint preview/commit; add line commit admission only after `LineMachine` owns concrete line result types. Integrate runtime commit delivery only after machines return typed commit intents. Repair the shared preview-publication path if needed so draw preview changes advance `state.revisions.preview` only and do not advance `state.revisions.document` or `state.revisions.interaction`; only effective mode/tool/style/color/pointer-policy setting changes may advance `state.revisions.interaction`. Update cleanup tests before relying on cleanup in load/surface tests. Expand public smoke after focused public draw behavior is stable. Update architecture graph, diagrams, docs, generated outputs, verification inventory, `PLAN.md`, and this step document after production declarations, tests, implementation review, and completion evidence exist. Do not mark `PLAN.md` or execution unit checkboxes complete during this planning step.

Temporal and all-or-nothing constraints:

Public observers may see preview changes during pointer sessions and committed document/action changes only after accepted edit install. The synchronous callback/public-observation surfaces are `CanvasToolPort.handlePointer`, public state listeners triggered by runtime state publication, `runtime.actions` listeners triggered by action stream delivery, commit effect observers, and reentrant public runtime calls attempted during delivery. `RuntimeRoot.ensureRuntimeMutationAllowed` and the existing runtime delivery guard own mutation rejection. Accepted stroke/line commit order is: normalize and validate terminal sample; interaction returns commit intent without document mutation; runtime allocates element id and constructs the public element; runtime prepares an interaction commit; edit callback calls `CanvasEdit.addElement`; `augmentPlan` appends exactly one draw action intent; post-success cleanup runs with `publish: false`; runtime publishes one accepted public state snapshot; runtime emits one draw action. Stale, invalid, no-op, cancel, load, dispose, and rollback paths emit no action and reserve no action timestamp.

All-or-nothing boundary: the irreversible document point is accepted `EditKernel` install. Terminal validation, point capping, style snapshot lookup, timestamp hint validation, generated id allocation, public element construction, and edit plan preparation are fallible before the irreversible point. After acceptance, cleanup, public state publication, repaint signaling, and action delivery are accepted post-commit effects. Edit failure after a draw commit intent routes through `PointerCleanupReason.editFailure`, clears preview/pending state as directed by the coordinator, publishes cleanup state only when needed, emits no action, leaves committed document state unchanged, and rethrows.
