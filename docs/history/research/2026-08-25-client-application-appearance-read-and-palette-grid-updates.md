# Research: Client Application Appearance Read and Palette/Grid Updates

## Summary

The client application's production adapter has one published-document read dedicated to the current canvas preset: `_presetFor` calls `runtime.readDocument().background` and maps background color plus grid enabled/cell size to `CanvasPreset` (`/Users/blackpika/client-application/lib/src/ui/lesson_editor/canvas_engine/lesson_editor_canvas_engine_adapter.dart:721`). Candidate loading and active-preset comparison reach that adapter method through `CanvasApplication` ports (`/Users/blackpika/client-application/lib/src/application/canvas/canvas_application.dart:408`, `/Users/blackpika/client-application/lib/src/application/canvas/canvas_application.dart:664`). A separate candidate-normalization transaction explicitly reads a full draft to preserve selected palette and grid values while replacing profile-owned values (`/Users/blackpika/client-application/lib/src/ui/lesson_editor/canvas_engine/lesson_editor_canvas_engine_adapter.dart:159`).

The maintained package publicly exposes full-document reads through `CanvasRuntime.readDocument()` and full-draft reads through `CanvasEdit.readDraftDocument()` (`lib/src/api/canvas_runtime.dart:37`, `lib/src/contracts/public/canvas_runtime.dart:158`). Palette, background color, and grid changes are currently whole-value setters on `CanvasEdit` (`lib/src/contracts/public/canvas_runtime.dart:171-173`). The document, background, grid, and palette value types, their defaulting, validation, immutability, exports, and Public API v1 documentation are present in the public contract (`lib/src/contracts/public/canvas_document.dart:14`, `lib/src/contracts/public/canvas_document.dart:142`, `lib/src/contracts/public/canvas_document.dart:219`, `docs/contracts/public_api_v1.md:745`).

Ordinary calls to those setters inside one edit session remain sparse until an explicit draft read promotes the session. The store replays the journal, validates the final candidate, compares it with the base document, and discards a net-unchanged candidate before installation (`lib/src/edit/edit_session.dart:683`, `lib/src/edit/edit_session.dart:406`, `lib/src/store/document_store_kernel.dart:824`). A full committed `CanvasDocument` is built by the projection cache only for `readDocument`; existing no-projection fixtures observe zero builds for ordinary sparse edits before an explicit read (`lib/src/store/document_projection_cache.dart:11`, `lib/src/store/document_store_kernel.dart:327`, `test/store/fixtures/no_projection_hot_path_fixture.dart:148`).

### 5. Sparse edit-session and Store path

- **Location**: `lib/src/edit/edit_kernel.dart:86`.
- **Description**: `EditKernel.edit` rejects nested sessions, executes the callback synchronously, rejects a `Future` callback result, and only prepares/installs a commit after normal callback return (`lib/src/edit/edit_kernel.dart:87`, `lib/src/edit/edit_kernel.dart:102`, `lib/src/edit/edit_kernel.dart:118`). It creates the sparse session with a lazy materialized-draft source (`lib/src/edit/edit_kernel.dart:220`, `lib/src/edit/edit_kernel.dart:228`).
- **Description**: Sparse `setBackgroundColor` uses the latest local background override or committed background, retains the current grid, appends `StoreSparseSetBackground`, marks background, and merges `StoreRevisionDelta.background()` (`lib/src/edit/edit_session.dart:683`, `lib/src/edit/edit_session.dart:699`). Sparse `setGrid` retains the current color, appends the same mutation type, marks grid, and merges `StoreRevisionDelta.grid()` (`lib/src/edit/edit_session.dart:702`, `lib/src/edit/edit_session.dart:717`). Sparse `setPalette` compares palette list contents, appends `StoreSparseSetPalette` when different, marks palette, and merges `StoreRevisionDelta.projectionOnly()` (`lib/src/edit/edit_session.dart:720`, `lib/src/edit/edit_session.dart:734`, `lib/src/edit/edit_session.dart:1096`).
- **Data flow**: Setter calls -> sparse journal -> Store transaction candidate -> ordered replay -> relationship/revision/deferred validation -> final candidate comparison -> prepared commit (`lib/src/store/document_store_kernel.dart:793`, `lib/src/store/document_store_kernel.dart:810`, `lib/src/store/document_store_kernel.dart:824`, `lib/src/store/document_store_kernel.dart:852`). - **Validation and atomicity**: The Store validates supplied revision-delta consistency and required revision coverage after replay (`lib/src/store/document_store_kernel.dart:2696`, `lib/src/store/document_store_kernel.dart:2756`). The sparse prepared commit installs only when it changed and its base revisions match current store revisions; `_document` is assigned at that install point (`lib/src/store/document_store_kernel.dart:1097`, `lib/src/store/document_store_kernel.dart:1107`). A callback exception does not reach acceptance/installation, and the edit kernel closes the session in `finally` (`lib/src/edit/edit_kernel.dart:96`, `lib/src/edit/edit_kernel.dart:118`).

### 6. Multiple mutations, no-op handling, revisions, and publication

- **Location**: `lib/src/edit/edit_session.dart:690`.
- **Description**: Each sparse setter first uses the current local override when one exists (`lib/src/edit/edit_session.dart:690`, `lib/src/edit/edit_session.dart:708`, `lib/src/edit/edit_session.dart:726`). Thus repeated background, grid, and palette calls in a single session append changes based on preceding local scalar state rather than independently rereading the committed values.
- **Description**: A setter does not append a mutation when its requested value equals the current local value (`lib/src/edit/edit_session.dart:692`, `lib/src/edit/edit_session.dart:710`, `lib/src/edit/edit_session.dart:728`). After journal replay, the Store compares the final candidate to its base; when the candidate has no final document change, it returns the base document with an empty revision delta and empty touched facts (`lib/src/store/document_store_kernel.dart:853`, `lib/src/store/document_store_kernel.dart:870`). The net-no-op fixture contains background and palette changes that return to their base values (`test/edit/fixtures/net_no_op_edit_commit_fixture.dart:50`, `test/edit/fixtures/net_no_op_edit_commit_fixture.dart:62`).
- **Description**: The accepted scalar delta is derived from final candidate-vs-base differences: palette requires projection-only, color requires background, and grid requires grid (`lib/src/store/document_store_kernel.dart:1827`, `lib/src/store/document_store_kernel.dart:1859`). Accepted touched facts record separate background, grid, and palette flags (`lib/src/store/document_store_kernel.dart:2473`, `lib/src/store/document_store_kernel.dart:2532`, `lib/src/store/document_store_kernel.dart:2626`, `lib/src/store/document_store_kernel.dart:2649`). `StoreRevisionDelta.merge` uses logical OR, so multiple mutations in one category yield one increment for that category when advanced (`lib/src/store/store_revision_delta.dart:84`, `lib/src/store/store_revision_delta.dart:110`).
- **Data flow**: accepted revision/touched facts -> `CommitPlan` -> installation/effects -> runtime delivery -> optional state/action publication (`lib/src/edit/edit_kernel.dart:337`, `lib/src/edit/edit_kernel.dart:357`, `lib/src/edit/commit_compiler.dart:57`, `lib/src/edit/commit_compiler.dart:90`, `lib/src/runtime/runtime_root.dart:2386`, `lib/src/runtime/runtime_root.dart:2469`). The commit compiler adds a projection effect when the projection revision changes, adds main repaint for background/grid but not palette-only changes, and adds a public-state effect for document revision (`lib/src/edit/commit_compiler.dart:57`, `lib/src/edit/commit_compiler.dart:67`, `lib/src/edit/commit_compiler.dart:80`, `lib/src/edit/commit_compiler.dart:90`).
