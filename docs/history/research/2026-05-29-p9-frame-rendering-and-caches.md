# Research: P9 Frame Rendering And Caches

## Summary

The current codebase contains the frame-adjacent boundaries P9 is expected to consume, but it does not contain a production frame renderer implementation yet. `FrameFactsPort` exists under `lib/src/contracts/internal/**`, and `RuntimeRoot` implements it by copying committed store facts into frame-facing DTOs (`lib/src/contracts/internal/frame_facts_port.dart:150`, `lib/src/runtime/runtime_root.dart:44`, `lib/src/runtime/runtime_root.dart:191`). `SelectionFactsPort` exists and is implemented by `SelectionKernel` (`lib/src/contracts/internal/selection_facts_port.dart:14`, `lib/src/selection/selection_kernel.dart:7`). P7 `SurfaceResourceSession` and P8 `SpatialKernel` are implemented in `lib/src/resources/**` and `lib/src/geometry/**` respectively (`lib/src/resources/surface_resource_session.dart:17`, `lib/src/geometry/spatial_kernel.dart:12`).

P9 frame rendering itself remains a documented future architecture obligation. The target `lib/src/frame/**` layout is documented as frame-private implementation names, not files created by the documentation step (`docs/architecture/02_package_boundaries.md:112`, `docs/architecture/02_package_boundaries.md:188`), and command evidence during this research found no `lib/src/frame/**` files and no `test/frame/**` directory. The architecture graph declares `frame.renderer`, `runtime.root.exposes_frame_facts`, and `frame.renderer.uses_surface_resource_session` as P9 future obligations (`docs/architecture/architecture_graph.yaml:398`, `docs/architecture/architecture_graph.yaml:602`, `docs/architecture/architecture_graph.yaml:774`).

The docs and verification ledgers already name P9 frame tests and guardrails, but the executable guardrail registry currently stops at P8 spatial/resource guardrails and has no frame/cache entries in `_blockingEntries` (`docs/verification/tests.md:305`, `docs/verification/guardrails.md:211`, `tool/guardrails/src/guardrail_registry.dart:35`, `tool/guardrails/src/guardrail_registry.dart:212`). Existing executable coverage is frame-adjacent: read-port shape, resource session behavior, spatial boundary behavior, runtime delivery ordering, and edit typed-effect independence from frame/resource/spatial owners.

## Observed Architecture Facts

- Pattern observed: P9 frame rendering is represented in docs and graph as future work, while production `lib/src/frame/**` files are absent in the current tree (`docs/implementation/p9_frame_rendering_and_caches.md:12`, `docs/architecture/architecture_graph.yaml:398`).
- Pattern observed: committed frame facts already have a contract-owned port and runtime-backed implementation (`lib/src/contracts/internal/frame_facts_port.dart:150`, `lib/src/runtime/runtime_root.dart:155`).
- Pattern observed: selection facts are separate from document facts and exposed through a contract-owned selection facts port (`lib/src/contracts/internal/selection_facts_port.dart:14`, `lib/src/selection/selection_kernel.dart:7`).
- Pattern observed: P7 resource session/cache ownership is implemented under resources and runtime dirty invalidation forwards to the active session through an internal sink (`lib/src/resources/surface_resource_session.dart:17`, `lib/src/runtime/runtime_root.dart:424`, `lib/src/runtime/runtime_root.dart:446`).
- Pattern observed: P8 spatial query code consumes `FrameFactsPort`, maintains hit/paint indexes, and returns typed query results (`lib/src/geometry/spatial_kernel.dart:35`, `lib/src/geometry/spatial_index_set.dart:9`, `lib/src/geometry/spatial_query_result.dart:3`).
- Pattern observed: executable guardrails currently include resource and spatial checks that are relevant to P9 boundaries, but frame/cache guardrail ids are documented rather than registered in `_blockingEntries` (`docs/verification/guardrails.md:211`, `tool/guardrails/src/guardrail_registry.dart:170`, `tool/guardrails/src/guardrail_registry.dart:212`).
- Data flow: edit or load commit -> typed delivery effects -> runtime spatial delivery -> runtime state publication -> observer callback (`lib/src/edit/commit_compiler.dart:59`, `lib/src/runtime/runtime_root.dart:522`, `lib/src/runtime/runtime_root.dart:550`).
- Data flow: resource dirty request -> `ResourceKernel` dirty outcome -> runtime active session invalidation -> runtime dirty state/effect publication (`lib/src/resources/resource_kernel.dart:40`, `lib/src/runtime/runtime_root.dart:424`, `lib/src/runtime/runtime_root.dart:446`, `lib/src/runtime/runtime_root.dart:559`).
