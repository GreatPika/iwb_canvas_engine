# Change Contract

## Goal

`clearContent` removes every element from ordinary document layers regardless of `isDeletable`, while preserving background metadata, grid metadata, background elements, and every resource still referenced by a preserved background element. Materialized edits, sparse edits, direct sparse-store commits, command preflight facts, returned removal lists, revisions, touched effects, spatial behavior, and command actions agree on that layer-only result without changing the public API shape or individual-deletion policy.

## Boundaries

Owner: The low-level `clearContent` semantic is one atomic edit/store seam jointly implemented by `DraftDocument`, sparse `EditSession`, and `DocumentStoreKernel`, with `ElementRegistry` and `FamilyTables` retaining their existing order and split resource-reference ownership and `ResourceTable` retaining descriptor mutation/publication ownership. Runtime command eligibility remains owned by `RuntimeCommandFactsAdapter`, and `RuntimeRoot` remains the command commit/action consumer. Public API, operation-matrix, edit, spatial, and verification documents remain the authoritative manual mirrors for their existing concerns.

In Scope: Clear every element from every ordinary `CanvasLayer` while retaining layer rows and metadata; preserve `CanvasBackground`, its grid, all `backgroundElements`, their order and values, and image/vector resource descriptors referenced by those preserved elements; remove other unused descriptors when requested through bounded owner-local materialized, sparse, store, and command-classification lifecycles; preserve journal order for add-before-clear, clear-before-add, `clear(true)`, resource, and remove-unused interleavings; report only actual removals; update materialized, sparse-session/promotion, direct sparse-store, command-facts, result/action, touched/revision/selection/spatial consequences; update existing authoritative prose and semantic-diagram mirrors; and extend nearest stable owner coverage with preserved background vector/resource and image/resource branches, a removed non-deletable ordinary-layer element, unchanged background/grid state, direct ordered-barrier evidence, and deterministic many-resource work evidence for each classification owner.

Out of Scope: Public method signatures, DTO shapes, action types, persisted document or codec schema, layer creation/removal/reordering, background-element mutation APIs, resource descriptor kinds, individual `removeElement` behavior, selection-delete eligibility, general `removeUnusedResource` behavior, generic commit/delivery architecture, architecture graph nodes or edges, new analyzers/guardrails/registries, and the active sparse transaction-candidate performance redesign are unchanged. Private helper, file, and class decomposition remains implementation-local; no new marker, retained-resource inventory, public seam, source scanner, parallel clear policy owner, or selectable old/new behavior is authorized.

Source of Truth: Materialized element objects and store-owned family rows plus their existing exact image/vector reference summaries remain the only resource-reference truth. Ordinary-layer membership remains in layer element order; background membership remains in background element order. Command facts derive from current frame/resource facts and do not become a second durable document model. Contract documents describe public and cross-owner effects but do not own copied element/resource inventories.

Compatibility: `CanvasEdit.clearContent` and `CanvasCommandPort.clearContent` keep their signatures, synchronous return type, result ordering contract, action type, timestamp behavior, stale-handle behavior, and no-action distinction. `removedElementIds` remains document-ordered but contains only removed ordinary-layer IDs; `removedResourceIds` contains only descriptors actually removed. Low-level clear emits no user action. Command clear emits one action only when ordinary-layer elements were removed; resource-only cleanup still emits no action. Existing individual removal and `deleteSelection` semantics remain unchanged. Persisted JSON, public DTOs, import/export, layer rows, camera, palette, metadata, background, grid, and background elements remain compatible. Reviewed design decisions D1-D20, including the new layer-only clear baseline and every existing architecture, complexity, ownership, journal-order, rollback, and delivery lock, remain authoritative; Contracts 2-4 consume this result without reinterpreting it.

Order Constraints: This behavior contract lands after the completed `authoritative-committed-facts` plan and before Contracts 2-4 of the active sparse transaction-candidate design. Unit 1 is the sole implementation unit and lands materialized clear, sparse candidate/overlay/result, direct store mutation, command preflight, public command expectations, spatial behavior, and authoritative mirrors as one atomic green cutover. Separating command facts, backing paths, spatial proof, or command/API expectations would leave either a failing direct consumer or a semantically false removable-facts mirror. Journal entries remain sequential: add/resource-upsert before clear participates in that clear; layer/content/resource additions after clear survive until affected by a later action; `clear(true)` evaluates unused descriptors against the exact intermediate post-layer-clear background state; and remove-unused before versus after clear retains its existing immediate decision point. All result/touched/revision/action facts derive from that ordered candidate. Later performance contracts preserve this new clear behavior while implementing their already-locked internal architecture and work bounds.

Temporal Surface Closure: Edit callbacks remain synchronous and non-nested; no new callback, await, stream, listener, or publication point is added. All element/resource/selection changes install atomically before runtime state and action publication. A background-only document with no removable unused resource is a no-op with no publication or action. Resource-only cleanup retains its current result/publication behavior and emits no action.

All-Or-Nothing Failure Boundary: Clear candidate construction, resource-reference decisions, store preparation, relationship admission, revision/touched derivation, and selection pruning remain inside the existing edit transaction. Any existing validation or preparation failure leaves committed elements, descriptors, selection, revisions, spatial/frame state, and action stream unchanged. No unit may temporarily clear background rows or descriptors and repair them after publication.

Negative Proof And Fixture Quarantine: Behavioral evidence uses real `CanvasVectorElement`/`CanvasVectorResource` and `CanvasImageElement`/`CanvasImageResource` pairs, distinct background and ordinary-layer locations, a non-deletable ordinary-layer element, unreferenced removable descriptors, and non-default background/grid values. Work evidence uses supported owner facts plus dormant assert-gated semantic events for descriptor-table lifecycle and split-summary reads. Assertions observe public documents, accepted store/frame facts, results, revisions/touched effects, action payloads, direct spatial paint queries, and semantic owner counters. Helper calls, private flags, copied expected inventories, wall-clock timing, source text, test-name tokens, or a green unrelated suite are rejected proxies. Fixtures remain under their mirrored edit, store, runtime, API, and spatial owners; no feature-local scanner or mixed-owner truth fixture is added.

Bounded Recognition Scope: No analyzer, guardrail, generated-output recognizer, schema scanner, import scan, or fixture-recognition mechanism changes. Behavioral tests invoke existing typed APIs and owners, so syntax-recognition bounds are not applicable to this contract.

Work Budget And Cost Displacement: This contract closes design D20's clear-specific budget without implementing the general transaction candidate, indexed sequences, or other Contracts 2-4 owners. Let `B` be current background-element count, `E` ordinary-layer element count, `H = B + E` current frame-handle count, and `R` current descriptor count. Materialized clear and promotion replay perform at most one background-reference pass and one resource pass, with no `R*B`/`R*H` scan. Sparse candidate classification enumerates current background IDs and current resource IDs once, resolves each committed background element at most once, performs no per-resource accepted-element scan, and does not project a public document. Direct store clear performs one descriptor-table mutation lifecycle, visits/copies each descriptor at most once, performs bounded split-summary reads with zero image/vector family-row visits per descriptor, and freezes/publishes the descriptor result at most once. Command preflight enumerates frame handles once, resolves each handle at most once, enumerates the resource catalog once, and performs no per-resource frame scan or projection. Runtime delivery does not classify retention; it consumes accepted resource IDs and remains covered by behavioral resource/spatial delivery evidence. The implementation may not loop immutable single-resource removal, rescan frame/family/background rows per descriptor, add a retained mirror, add an extra immutable publication, or repair state after install. Existing assert-gated owner observation, fixture fact-port counters, and `FamilyTables` telemetry may be extended only with semantic events needed to prove these bounds; they retain no production history or counters.
